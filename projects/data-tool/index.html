01 — OVERVIEW

THE
OVERVIEW

一个艺人跨平台内容数据统计工具。输入艺人主页与时间范围，自动汇总各平台的发布条数，并输出竞品对比。

界面刻意做得很薄。用户只需要两个输入：艺人主页 + 时间范围，其他都不需要。

02 — PROBLEM

THE
PROBLEM

需求来自微博实习的真实痛点：人工统计艺人各平台发布数据，单次耗时约 20 分钟、容易遗漏，而且几乎没法横向对比竞品。

  • 单次统计约 20 分钟，且需要反复进行。
  • 人工操作容易漏项，漏一条就会得出错误结论。
  • 想做竞品对比，就得把整套流程再手工做一遍。
03 — THINKING

THE
THINKING

把重复劳动交给工具。输入只应该是「艺人主页 + 时间范围」，其余都是工具要解决的问题，不是用户要解决的问题。

所以 MVP 的范围自然就定了：不做账号体系、不做仪表盘、不做设置项。一个页面、两个输入、一张可以直接截图进报告的表。

04 — PROCESS

THE
PROCESS

需求
把实习中的痛点拆解为产品需求。
逻辑
明确什么算「一条发布」，以及时间范围如何映射到各平台。
实现
使用 Claude Code 完成 MVP。
核对
与人工复核结果逐项对照。
对比
把竞品对比做成第二组输出。
迭代
修掉真实使用中发现的统计偏差。
05 — SOLUTION

THE
SOLUTION

输入艺人主页与时间范围，自动汇总多平台发布条数，并输出竞品对比。

  • 覆盖 3 个平台，数据与人工复核一致。
  • 单次统计耗时从约 20 分钟降至 5 秒。
  • 竞品对比从「再做一遍」变成顺手得到的副产品。
06 — RESULT

THE
RESULT

热门平台发布条数与人工复核结果一致，覆盖 3 个平台，单次统计耗时从约 20 分钟降至 5 秒。

  • 20min→5s单次统计耗时
  • 3覆盖平台
  • 1MVP已上线版本
  • 100%与人工复核一致

08 — REFLECTION

WHAT I
LEARNED

最有用的产品决定其实是「不做」：不做仪表盘、不做登录、不做配置项。一个能塞进一屏的工具，才是当天就能被真正用起来的工具。

另外我也学到：验证一个工具，要拿它和「被它替代的人工流程」对照，而不是只看它自己输出的结果。
